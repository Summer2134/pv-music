# Как я работаю с ИИ

Весь проект PV Bot и этот музыкальный бот сделаны через ИИ-агентов. Код пишут агенты, а я веду продукт: ставлю задачу, проверяю результат и решаю, что выкатывать.

## Команда

| Кто | Что делает |
|---|---|
| **Claude Code** (два параллельных агента) | логика, база, интеграции, тесты, деплой |
| **Codex** | картинки и ассеты: арты питомцев, фоны, значки кнопок плеера, баннеры |
| **Я** | что делать и зачем, приоритеты, приёмка, общение с участниками сервера |

Агенты не теряют контекст между сессиями:
- **`CLAUDE.md`** — память проекта: стек, правила, решения, история каждой фичи. Агент читает его перед задачей и дописывает после.
- **`CLAUDE-SYNC.md`** — общий пульт команды: кто чем занят, очередь задач, записки друг другу. Два Claude и Codex не правят одно и то же.
- **Задания для Codex** — отдельные файлы `docs/codex/*.md`. В каждом: размеры, стиль, ограничения CPU и лимиты Discord, куда класть результат.

## Свои Skills и агенты Claude

- **`new-feature`** — чек-лист новой команды: регистрация, справка, тесты, лимиты Discord.
- **`deploy`** — порядок выкладки.
- **`bot-reviewer`** — ревью диффа перед main: баги, правила проекта, устойчивость к падению базы, экономика.
- **`idea-designer`** — идеи новых фич под живой сервер.

## Как проверяется результат ИИ

1. **Автотест на каждую фичу.** Это обычные Node-скрипты с `assert`: временная база (PGlite или PostgreSQL), подставной Discord, подставные внешние API. Фича считается готовой, только когда тест зелёный. В основном проекте таких наборов 80.
2. **Тест сначала ловит баг, потом фиксирует исправление.** Пример: поиск текста «101 причина» VILLIAN нашёл одноимённую песню Kai Angel. Сначала появился тест с этим случаем, потом сверка исполнителя.
3. **Лимиты Discord проверяет скрипт**, а не человек на глаз: длина эмбедов, число кнопок в ряду, размер справки.
4. **Диагностика в проде.** Если что-то не работает только на сервере, бот сам показывает, где сломалось:
   - `!!!test` — звук по шагам: ffmpeg → yt-dlp → client_id → поиск → ссылка на звук → Lavalink;
   - `!!!текст` — что ответил каждый источник текстов;
   - `!!!сайт` — открыть страницу с сервера и прислать её файлом.

## Пример: как нашли и решили проблему со звуком

| Шаг | Что увидели | Что сделали |
|---|---|---|
| 1 | YouTube на сервере: «Sign in to confirm you're not a bot» | Перешли на SoundCloud |
| 2 | SoundCloud в Lavaplayer: «Did not detect any supported formats» | Свой клиент к API SoundCloud и свой стрим через ffmpeg |
| 3 | В логах сервера «SoundCloud 404» на каждом треке | HLS первым в списке форматов, запасные пути: свежая авторизация и yt-dlp |
| 4 | «Ничего не нашёл», хотя поиск работает | Ревью агента нашло причину: Lavalink ждёт ответа 3 с, а поток не успевал. Подняли таймауты, заголовки шлём после первых байт ffmpeg |
| 5 | Заиграло | Самопроверка `!!!test` после каждого перезапуска, отчёт владельцу в ЛС |

Каждый шаг — отдельный коммит с тестом. Подставной ffmpeg лежит в `scripts/fakes/`.

## Долгая автономная работа

Большие куски делаются «ночными прогонами»: агент получает список задач (в одном прогоне было 120), работает в отдельной ветке, гоняет тесты после каждой задачи и пишет утренний отчёт. Утром я принимаю работу и вливаю в main.
